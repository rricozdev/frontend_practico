# 📘 Clase Completa: React-Redux para Dummies 

---

## 🔥 1. ¿Qué es Redux?

Redux es una librería para manejar el **estado global** de tu aplicación. Es útil cuando tienes información que muchos componentes necesitan (usuario logueado, carrito, contador, etc.).

### En React puro usamos:

```js
const [contador, setContador] = useState(0);
```

Eso funciona bien… **al principio**. Pero en una app más grande:

* Varios componentes necesitan el mismo estado.
* Se vuelve difícil pasar datos de un lugar a otro.
* Terminas con “prop drilling” y desorden.

**Redux soluciona esto con:**

* Un **store** único que contiene el estado.
* Un sistema claro y predecible para modificarlo.

---

## 🧠 2. Redux explicado como un banco

| Concepto | ¿Qué es?                       | Metáfora           |
| -------- | ------------------------------ | ------------------ |
| Store    | Donde vive el estado           | El banco           |
| Action   | Lo que se quiere hacer         | El formulario      |
| Reducer  | La lógica que aplica el cambio | El cajero          |
| Dispatch | Cómo se envía la acción        | Ir a la ventanilla |
| State    | Estado actual del store        | Tu saldo           |

---

## ❗ 3. ¿Qué problema resuelve Redux?

### 🔥 El "prop drilling"

Pasar props por muchos componentes intermedios cuando solo uno los necesita:

```jsx
<App>
 └── <Layout>
      └── <Sidebar>
           └── <Perfil>
                └── <Avatar nombre="Cami" />
```

Con Redux puedes hacer esto:

```js
const nombre = useSelector(state => state.usuario.nombre);
```

Sin tener que pasar `props` por todos los niveles.

## 🧪 4. ¿Qué hicimos en clase? – Construyendo Redux paso a paso

---

### 📄 1. Creamos acciones

```js
// actions.js
export const INCREMENTAR = "INCREMENTAR";
export const DECREMENTAR = "DECREMENTAR";
```

✅ Usamos constantes para evitar errores de tipeo (`"INCRMENTAR"`).

---

### 📄 2. Creamos el reducer

#### Versión 1: **Estado primitivo**

```js
// reducer.js
const initialState = 0;

function contadorReducer(state = initialState, action) {
  switch (action.type) {
    case INCREMENTAR:
      return state + 1;
    case DECREMENTAR:
      return state - 1;
    default:
      return state;
  }
}
```

✅ Ideal para estados simples, como un número.
❌ Limitado: no puedes tener más propiedades.

---

#### Versión 2: **Intento de pasar a objeto (incorrecto)**

```js
const initialState = 0;
// const initialState = { value : 0 }

function contadorReducer(state = initialState, action) {
  switch (action.type) {
    case INCREMENTAR:
      return {
        value: state + 1  // 🚫 Incorrecto: mezcla tipos
      };
    default:
      return state;
  }
}
```

❗ Este cambio rompe el estado porque `state` es un número, no un objeto.

---

#### Versión 3: **Estado como objeto (correcto)**

```js
const initialState = { value: 0 };

function contadorReducer(state = initialState, action) {
  switch (action.type) {
    case INCREMENTAR:
      return {
        ...state,
        value: state.value + 1
      };
    case DECREMENTAR:
      return {
        ...state,
        value: state.value - 1
      };
    default:
      return state;
  }
}
```

✅ Esta es la forma correcta cuando el estado es un **objeto**.
✅ Usamos el operador **spread (`...state`)** para **no perder otras propiedades** del estado.

---

#### ❌ Error común a evitar:

```js
return {
  value: ...state.value + 1 // 🚫 SyntaxError: ... sólo funciona con objetos/arrays
}
```

✅ Explicar que `state.value` es un número, y no puede “descomponerse” con `...`.

---

### 📦 3. Creamos el store

```js
// store.js
import { compose, createStore } from "redux";
import contadorReducer from "./reducer";

// ⚠️ REDUX DEVTOOLS - Error común: usar mal los guiones bajos
const composeEnhancers = window.__REDUX_DEVTOOLS_EXTENSION_COMPOSE__ || compose;

const store = createStore(contadorReducer, composeEnhancers());

export default store;
```

💬 *Error común para explicar en clase:*

```js
window._REDUX_DEVTOOLS_EXTENSION_COMPOSE_ // ❌ Mal escrito
```

La forma correcta es como se ve:

```js
const composeEnhancers = window.__REDUX_DEVTOLLS_EXTENSION_COMPOSE__ || compose;

// doble underscore "__" no uno "_" ojo al principio y al final.
```

---

### 🧠 4. Conectamos Redux a React

```jsx
// main.jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
import { Provider } from 'react-redux';
import store from './redux/store';

ReactDOM.createRoot(document.getElementById('root')).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

📌 `Provider` hace que **todos los componentes React tengan acceso al store**.

---

### 🔢 5. Componente `Contador`

```jsx
// Contador.jsx
import { useDispatch, useSelector } from 'react-redux';
import { INCREMENTAR, DECREMENTAR } from '../redux/actions';

function Contador() {
  const contador = useSelector(state => state.value); 
  const dispatch = useDispatch();

  return (
    <div>
      <h1>Contador: {contador}</h1>
      <button onClick={() => dispatch({ type: INCREMENTAR })}>+</button>
      <button onClick={() => dispatch({ type: DECREMENTAR })}>-</button>
    </div>
  );
}

export default Contador;
```

## ✅ 6. Buenas prácticas

| Hacer esto...                              | No hacer esto...                          |
| ------------------------------------------ | ----------------------------------------- |
| ✅ Usar constantes para `action.type`       | ❌ Escribir strings directamente           |
| ✅ Usar `...state` al modificar el reducer  | ❌ Modificar el estado directamente        |
| ✅ Organizar Redux en carpeta `/redux`      | ❌ Mezclar Redux con lógica de componentes |
| ✅ Usar `useSelector` solo con lo necesario | ❌ Leer todo el estado si no lo necesitas  |

---

## 🧬 7. Evolución del `initialState`: de simple a profesional

| Etapa                   | Código                                        | Comentario                                          |
| ----------------------- | --------------------------------------------- | --------------------------------------------------- |
| Básico                  | `const initialState = 0;`                     | Ideal para estados primitivos simples.              |
| Transición (incorrecta) | `return { value: state + 1 }`                 | Mezcla tipos: error típico al migrar a objeto.      |
| Correcto (objeto)       | `const initialState = { value: 0 };`          | Escalable y compatible con estructuras más grandes. |
| Copia del estado        | `return { ...state, value: state.value + 1 }` | Patrón correcto para evitar mutación directa.       |
